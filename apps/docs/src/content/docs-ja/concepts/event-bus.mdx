## 概要

`EventBus` により、プラグイン同士が直接依存せずに通信できます。あるプラグインがイベントを発行し、任意の数のプラグインがそれを購読できます。

## API

```ts
interface EventBus {
  // 既知の CoreEventMap イベントは型付きオーバーロードで emit/on できる
  on<K extends keyof CoreEventMap>(event: K, handler: (data: CoreEventMap[K]) => void): () => void;
  on<T = unknown>(event: string, handler: (data: T) => void): () => void;
  emit<K extends keyof CoreEventMap>(event: K, data: CoreEventMap[K]): void;
  emit<T = unknown>(event: string, data: T): void;
  pause(): void;    // イベント配信を一時停止（参照カウント式。ネスト可）
  resume(): void;   // pause を 1 つ解除。カウントが 0 になると配信再開
  isPaused(): boolean;
}
```

- `on()` は購読解除用の関数を返します。`setup` からその関数を返して後片付けしてください。
- `emit()` は同期的にそのイベントの全ハンドラを呼び出します。
- `CoreEventMap` に定義された既知イベント（`canvas:pointerdown` など）は型安全な `emit`/`on` のオーバーロードが効きます。未知の文字列イベントは `T = unknown` フォールバックで扱えます。
- `pause()` / `resume()` は参照カウント式で、配信を一時停止できます。各 `pause()` は必ず対応する `resume()` と対で呼び出してください（`pause()` をリークすると以降のイベントが全て破棄されます）。`isPaused()` で現在の状態を確認できます。

## ストア変更のブリッジ

コアは `BoardStore` の変更を `EventBus` へ自動的にブリッジします。ストア経由でシェイプが追加・更新・削除されると、対応する変更イベントがバスに emit されます。

```ts
// コア内部で自動的に行われる処理：
store.onMutation((event) => {
  events.emit(event.type, event.payload);
});
```

つまりプラグインは、ストアに直接購読しなくてもストアの変更を観測できます。

## 使用例：スナッププラグイン

```ts
const snapPlugin: UsketchPlugin = {
  id: "usketch-plugin-snap",
  name: "Snap",

  setup(ctx: PluginContext) {
    // on() が返す購読解除関数を、そのまま setup の teardown として返す
    return ctx.events.on("tool:drag", (event) => {
      const snapped = calculateSnap(event.point, event.shapes);
      updateSnapGuides(snapped);
    });
  },
};
```

複数の購読を解除する場合は、クロージャでまとめた関数を返します：

```ts
const multiPlugin: UsketchPlugin = {
  id: "usketch-plugin-multi",
  name: "Multi",

  setup(ctx: PluginContext) {
    const offDrag = ctx.events.on("tool:drag", handleDrag);
    const offDrop = ctx.events.on("canvas:drop", handleDrop);
    return () => {
      offDrag();
      offDrop();
    };
  },
};
```

## イベント命名規約

イベントバスは完全に動的（任意の文字列が使えます）ですが、以下のパターンを推奨します：

| パターン | 例 | 説明 |
|---------|---------|-------------|
| `{system}:{action}` | `tool:activate` | コアシステムのイベント |
| `shape:{action}` | `shape:added` | シェイプライフサイクルのイベント |
| `plugin:{id}:{action}` | `plugin:snap:calculated` | 特定プラグインのイベント |

## ヒント

- イベントのペイロードは可能な限り**シリアライズ可能**に保つ — デバッグや将来の同期シナリオで有効。
- プラグイン間の直接 import より、イベントを優先する。プラグイン A がプラグイン B のデータを必要とするなら、内部 API を露出させる代わりに B からイベントを発行させる。
- `EventBus` は同期的です。非同期処理が必要ならハンドラ内で扱ってください。
