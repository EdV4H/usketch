`@edv4h/usketch-core` パッケージはアプリケーションのブートストラップ関数を提供します。

## createApp

```ts
import { createApp } from "@edv4h/usketch-core";

const app = await createApp({
  store: myBoardStore,
  plugins: [selectPlugin, panPlugin, rectPlugin, /* ... */],
});
```

### CreateAppOptions

```ts
interface CreateAppOptions {
  store: BoardStore;
  plugins: UsketchPlugin[];
  lod?: {
    policy?: LodPolicy;
    initialMode?: RenderMode;
  };
  selectionForeground?: Pick<SelectionForeground, "render"> &
    Partial<Pick<SelectionForeground, "priority" | "order" | "fixed">>;
}
```

| フィールド | 説明 |
|-------|-------------|
| `store` | 必須。`BoardStore` インスタンス（通常は `@edv4h/usketch-store` で生成）。 |
| `plugins` | 必須。初期化するプラグインの配列。順序は重要 — 逐次 setup される。 |
| `lod?` | 任意。LOD（詳細度）設定。省略時は zoom + シェイプ数の複合ポリシー、`interactive` モード開始のデフォルトが使われる。 |
| `selectionForeground?` | 任意。デフォルトの選択 UI（ハンドル・バウンディングボックス・マーキー）をホスト実装で置き換える。内部で priority 100 として登録され、プラグインのデフォルトより優先される。 |

### AppInstance

`createApp` の戻り値：

```ts
interface AppInstance {
  store: BoardStore;
  layers: LayerManager;
  tools: ToolRegistry;
  shapes: ShapeRegistry;
  commands: CommandRegistry;
  shortcuts: ShortcutRegistry;
  events: EventBus;
  transient: TransientRegistry;
  lod: LodController;
  ui: UiRegistry;
  selectionForeground: SelectionForegroundRegistry;
  externalContent: ExternalContentRegistry;
  actions: ActionRegistry;
  services: ServiceRegistry;
  plugins: readonly UsketchPlugin[];
  destroy(): void;
}
```

`createApp` が解決された時点で、すべてのレジストリは populated されています。プラグインが登録したものを調べるにはこれらのレジストリを参照できます。

### destroy()

アプリを破棄するには `destroy()` を呼びます：

```ts
app.destroy();
```

これは各プラグインの `setup()` が**返した**ティアダウンクロージャを、**登録の逆順（LIFO）**で実行し、その後 LOD コントローラを破棄し、内部の購読を解除します（`plugin.teardown()` を登録順に呼ぶのではありません）。ティアダウンは sync / async どちらでもよく、`destroy()` 自体は同期のまま async ティアダウンは fire-and-forget（エラーはログ出力）で扱われます。

## 初期化フロー

```
createApp({ store, plugins })
  │
  ├─ レジストリを生成
  │   ├─ LayerManager
  │   ├─ ToolRegistry
  │   ├─ ShapeRegistry
  │   ├─ CommandRegistry
  │   ├─ ShortcutRegistry
  │   ├─ EventBus
  │   └─ TransientRegistry
  │
  ├─ ストアの変更を EventBus にブリッジ
  │
  ├─ 各プラグインについて：
  │   ├─ PluginRegistry に登録
  │   └─ await plugin.setup(ctx)
  │
  ├─ コアのショートカットを登録
  │   ├─ Ctrl+Z → undo
  │   └─ Ctrl+Shift+Z → redo
  │
  └─ AppInstance を返す
```

## エラーハンドリング

いずれかのプラグインの `setup()` が throw した場合、`createApp` は次を行います：

1. すでに収集済みのティアダウン（先行して setup 済みのプラグインが返したもの）を**逆順（LIFO）で実行**し、部分的に初期化された状態がリークしないようロールバックする。
2. ストア変更の購読を解除。
3. エラーを再 throw。

つまり先行プラグインのティアダウンは**実行されます**。とはいえ、部分的に初期化された状態でも安全になるようプラグインを設計するのが望ましいです。

## React との連携

通常はアプリインスタンスを 1 回作成し、React のコンテキスト経由でレジストリを提供します：

```tsx
const app = await createApp({ store, plugins });

function App() {
  return (
    <UsketchProvider app={app}>
      <Canvas />
      <Toolbar />
      <PropertyPanel />
    </UsketchProvider>
  );
}
```

`UsketchProvider` や React 統合コンポーネントは `apps/web` の一部であり、core パッケージには含まれていません。
