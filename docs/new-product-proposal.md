# 新プロダクト企画書: uSketch v2

**作成日**: 2026-03-14
**ステータス**: 企画段階

---

## 1. エグゼクティブサマリー

前身プロジェクト uSketch の技術的知見を活かし、**「誰でもすぐに使えるリアルタイムコラボレーション・ホワイトボード」** を開発する。

前プロジェクトの最大の教訓は「優れたアーキテクチャがあっても、保存・共有・コラボレーションがなければプロダクトにならない」こと。v2ではMVPの段階からこれらの機能を含め、**ユーザーが実際に使い続けられる状態**を最速で実現する。

---

## 2. プロダクトビジョン

### 2.1 ターゲットユーザー

| ペルソナ | ニーズ | 利用シーン |
|----------|--------|------------|
| **リモートチーム** | ブレインストーミング、設計レビュー | ミーティング中のリアルタイム共同作業 |
| **プロダクトマネージャー** | ワイヤーフレーム、フロー図 | 要件定義、アイデア整理 |
| **教育者** | 図解、板書の代替 | オンライン授業、ワークショップ |
| **個人ユーザー** | メモ、アイデアスケッチ | 日常的な思考整理 |

### 2.2 コアバリュー

1. **即座に使える**: アカウント不要でURLを開くだけで描き始められる
2. **リアルタイム共同作業**: リンクを共有するだけで複数人が同時に編集
3. **軽量で高速**: ブラウザだけで動作、インストール不要
4. **保存と共有**: 自動保存、PNG/SVG/PDFエクスポート、リンク共有

### 2.3 競合分析

| 製品 | 強み | 弱み | uSketch v2の差別化 |
|------|------|------|-------------------|
| Excalidraw | OSSの手書き風、シンプル | コラボレーションが有料 | OSSでリアルタイムコラボ |
| Miro | 豊富なテンプレート | 重い、高価格 | 軽量、無料利用可能 |
| tldraw | 優れたUX、OSS | エンタープライズ機能不足 | プラグイン拡張性 |
| FigJam | Figmaエコシステム | Figma依存 | 独立して動作 |

## 3. MVPスコープ（Phase 1）

### 3.1 MVP機能一覧

前プロジェクトの「まず技術基盤を完璧にする」アプローチを避け、**ユーザーが価値を感じる最小セット**を定義。

#### 必須機能（Must Have）

| 機能 | 説明 | 前プロジェクトからの流用 |
|------|------|------------------------|
| **基本描画** | 矩形、楕円、フリーハンド、テキスト | ✅ ツールシステム・形状プラグイン |
| **選択・移動・リサイズ** | シェイプの操作 | ✅ 選択ツール状態マシン |
| **Undo/Redo** | 操作の取り消し・やり直し | ✅ コマンドパターン |
| **自動保存** | ブラウザローカル + クラウド同期 | 🆕 新規実装 |
| **エクスポート** | PNG、SVGでの書き出し | 🆕 新規実装 |
| **リンク共有** | URLでボードを共有 | 🆕 新規実装 |
| **リアルタイムコラボ** | 複数人の同時編集、カーソル共有 | 🆕 新規実装 |

#### あると良い機能（Should Have）

| 機能 | 説明 |
|------|------|
| スナップ・ガイド | グリッドスナップ、スマートガイド（前プロジェクトの資産を活用） |
| スタイリング | 色、線幅、透明度の変更 |
| テンプレート | 会議用、ブレスト用などのテンプレート |
| PDFエクスポート | 印刷用フォーマット |

#### 将来対応（Nice to Have）

| 機能 | 説明 |
|------|------|
| プレゼンテーションモード | フルスクリーンプレゼン |
| AI機能 | テキストから図の自動生成 |
| プラグインマーケットプレイス | サードパーティ拡張 |
| ネイティブアプリ | デスクトップ/モバイル対応 |

### 3.2 ユーザーストーリー（MVP）

```
[US-01] ユーザーとして、URLを開くだけで新しいホワイトボードを作成できる
[US-02] ユーザーとして、矩形・楕円・フリーハンド・テキストを描画できる
[US-03] ユーザーとして、描画したシェイプを選択・移動・リサイズ・削除できる
[US-04] ユーザーとして、操作を元に戻したりやり直したりできる
[US-05] ユーザーとして、ボードが自動的に保存される
[US-06] ユーザーとして、ボードをPNG/SVGとしてエクスポートできる
[US-07] ユーザーとして、リンクを共有して他のユーザーを招待できる
[US-08] ユーザーとして、他のユーザーのカーソル位置と編集がリアルタイムに見える
[US-09] ユーザーとして、同時編集で競合が自動的に解決される
```

## 5. 開発ロードマップ

### Phase 1: MVP（8週間）

**Week 1-2**: プロジェクトセットアップ + コア描画エンジン
- モノレポセットアップ（パッケージ数を削減して開始）
- 前プロジェクトからツールシステム・形状システムを移植
- テキストツールの新規実装

**Week 3-4**: 永続化 + エクスポート
- ローカルストレージ自動保存
- クラウド保存API（Supabase or Cloudflare D1）
- PNG/SVGエクスポート

**Week 5-6**: リアルタイムコラボレーション
- WebSocket基盤（Cloudflare Durable Objects or PartyKit）
- CRDT（Yjs）による状態同期
- カーソル共有・プレゼンス表示

**Week 7-8**: 共有 + 仕上げ
- リンク共有・アクセス制御
- UIポリッシュ、パフォーマンスチューニング
- ベータリリース

### Phase 2: 成長（4週間）

- ユーザーフィードバック対応
- スナップ・ガイド機能の統合（前プロジェクトの資産を移植）
- テンプレートシステム
- PDFエクスポート
- 認証・アカウント管理

### Phase 3: 収益化（4週間）

- 課金基盤（Stripe）
- Pro/Teamプランの実装
- チーム管理機能
- ボード一覧ダッシュボード

### Phase 4: 拡張（継続的）

- プラグインAPI
- AI機能（テキスト→ダイアグラム）
- モバイル対応
- API公開

## 7. リスクと対策

| リスク | 影響度 | 対策 |
|--------|--------|------|
| 前プロジェクトと同じく基盤に時間を費やしすぎる | 高 | MVPの厳格なスコープ管理。8週間のタイムボックス |
| リアルタイム同期の技術的困難 | 中 | Yjs等の実績あるCRDTライブラリを採用。自前実装しない |
| 競合の急速な進化 | 中 | OSSコアによる差別化、コミュニティ構築 |
| チームの確保 | 高 | 初期は2-3名で開始、MVPの成果でチーム拡大の根拠とする |
| サーバーコスト | 低 | Edge Runtime（Cloudflare Workers）でコスト最小化 |
