# PRD: uSketch — もっとも AI ネイティブな GUI コラボレーションツール

## Context

uSketch v2 は MVP ロードマップ（8週間）で基本的なホワイトボード機能（描画・永続化・コラボ・共有）を構築中。ここに新たなプロダクトビジョンとして「AIネイティブ」を掲げ、競合（Miro AI / FigJam AI / tldraw Make Real）との根本的な差別化を図る。

v1 の教訓「ユーザー価値を先に出せ」を守りつつ、AI を後付け機能ではなくアーキテクチャレベルで組み込む方針を定義する。

---

## 1. ビジョン: 「AI ネイティブ」とは何か

### AI-augmented（競合）vs AI-native（uSketch）

| | AI-augmented | AI-native |
|---|---|---|
| AI の居場所 | サイドバー / モーダルダイアログ | キャンバス上（他のユーザーと同じ空間） |
| AI の出力 | バッチ生成 → 一括挿入 | ストリーミングで目の前に描画 |
| AI のキャンバス認識 | スクリーンショット or 限定API | `Y.Map<ShapeData>` を直接読み書き |
| AI のコラボ参加 | 生成結果は静的 | Yjs セッションにリアルタイム参加 |
| Undo | AI操作のUndoが不完全 | CommandRegistry 経由で完全Undo |
| 拡張性 | ベンダー定義のAI機能のみ | 誰でもAIプラグインを作れる |

### ポジショニング

> uSketch は、AI がメニューの一機能ではなくキャンバス上の共同作業者として振る舞う、初めてのホワイトボード。すべての AI アクションが人間と同じ CRDT・プラグイン・プレゼンスシステムを流れるから、AI の支援がネイティブに感じられる。

### なぜ uSketch がこれをできるのか

1. **プラグインアーキテクチャ** — AI 機能を標準 `UsketchPlugin` として実装。core パッケージは変更不要
2. **型付き ShapeData** — `[key: string]: unknown` 拡張可能な構造がそのまま LLM の入出力フォーマットになる
3. **Yjs CRDT** — AI の書き込みが自動的に全クライアントに同期。特別な配管不要
4. **TransientRegistry** — AI のカーソル・思考中インジケータ・提案ゴーストを既存の仕組みで表示
5. **EventBus** — AI が `shape:added`, `selection:changed` を購読して文脈を理解

## 2. コア AI 機能

### 2.1 Canvas-Aware AI Agent（基盤レイヤー）

AI を Yjs Awareness のピアとしてボードに接続。他ユーザーと同じプレゼンス（カーソル・選択・色）を持つ。

- キャンバスの `ShapeData` マップを読み取り、LLM に構造化コンテキストとして渡す
- AI の操作は `CommandRegistry.execute()` 経由で `BoardStore` を変更（全操作が Undo 可能）
- プラグイン: `usketch-plugin-ai-agent`

### 2.2 Natural Language → Canvas（NL2Canvas）

ユーザーが自然言語で指示 → AI がキャンバス上にシェイプを配置。

- コマンドパレット（Cmd+K 的UI）またはチャットパネルから入力
- AI がリアルタイムでシェイプを配置する様子が見える（ストリーミング）
- 出力は編集可能な標準シェイプ（画像ではない）
- 例:
  - 「ログイン → ダッシュボード → 設定のユーザーフローを作って」
  - 「緊急/重要の2x2マトリクスを作って」
  - 「ログインページのワイヤーフレームを描いて」

### 2.3 Canvas Understanding（Visual2Context）

AI がキャンバスを読み取り、文脈に応じた支援を提供。

- 「このボードを要約して」— 全テキストシェイプと空間的関係を分析
- 「このフローに足りないものは？」— 接続されたシェイプを分析、欠落を指摘
- 選択中のシェイプに基づくコンテキスト提案

### 2.4 Real-Time Copilot（リアルタイム共同制作）

AI が EventBus イベントを監視し、ゴーストシェイプとして提案をリアルタイム表示。

- `shape:added`, `shape:updated` を購読
- 提案は TransientRegistry の `ai-suggestion` タイプ（半透明、クリックで確定、Esc で却下）
- 例:
  - フローチャートのボックスを描く → AI が次のボックスと矢印を提案
  - 付箋を作る → AI が関連カテゴリを提案
- デバウンスされた推論（毎ポインタ移動では呼ばない）

### 2.5 Smart Actions（選択シェイプへのAIアクション）

コンテキストメニューからのAI操作。

- 「きれいにして」— スタイル・整列・間隔を調整
- 「フローチャートに変換」— 散らばったシェイプを接続されたフローに再配置
- 「ラベルを付けて」— 空間レイアウトを読み取り、説明テキストを追加
- 「翻訳して」— 選択シェイプのテキスト言語を変更
- 「トピック別にグループ化」— 意味的にクラスタリングしてグループ化

### 2.6 マルチモーダル入力（将来）

- 音声 → キャンバス（Web Speech API → コマンド or テキストシェイプ）
- 画像 → シェイプ（アップロード → 構造抽出 → 編集可能シェイプ）
- 手書き認識（フリーハンドストローク → テキスト or 幾何図形）

## 3. ユーザーシナリオ

### シナリオ A: リモートチームのブレインストーミング

1. PM がコマンドパレットに入力:「モバイルアプリのオンボーディングについてブレストのキャンバスを作って」
2. AI がタイトル・カテゴリ見出し・シードアイデアを生成
3. チームメンバーがリンクで参加、AI 生成の足場を見る
4. チームがアイデアを追加すると、AI が関連クラスタの近くに「こんなのも考えては？」とゴースト提案
5. PM が「テーマ別に整理して」→ AI がシェイプをグループに再配置
6. PM が「成果を要約して」→ AI が全シェイプを読み、サマリーテキストシェイプを生成

### シナリオ B: 個人のアイデアスケッチ

1. 空のボードに四角を描いて「ログイン」と書く
2. AI がUIフローの開始と認識、「ログイン後は何？」とゴースト提案
3. ユーザーが一部を採用・修正。AI が進化するコンテキストに応じて提案を適応
4. 「ちゃんとしたワイヤーフレームにして」→ AI がラフスケッチを整形

### シナリオ C: 教育者のレッスン作成

1. 「水循環の図を作って」と入力
2. AI が蒸発・凝結・降水をラベル付きシェイプ+矢印で生成
3. 教師が位置を調整、注釈を追加
4. AI が編集を検知し、矢印の接続を自動調整

### シナリオ D: デザインレビュー会議

1. デザイナーがワイヤーフレーム付きボードを共有
2. レビュアーがセクションを選択「このあたりのアクセシビリティの問題は？」
3. AI がシェイプ・テキストサイズ・カラーコントラストを分析、注釈シェイプで問題をハイライト

## 4. 技術アプローチ

### 4.1 原則: AI はプラグイン、プラットフォームではない

すべての AI 機能は標準 `UsketchPlugin` として実装。`packages/core` は AI のために変更しない。

### 4.2 プラグイン構成

```
plugins/
  usketch-plugin-ai-agent/        — 基盤: AI プレゼンス、キャンバス読取、LLM ブリッジ
  usketch-plugin-ai-chat/         — チャットパネル UI + NL2Canvas コマンド
  usketch-plugin-ai-copilot/      — リアルタイム提案エンジン（ゴーストシェイプ）
  usketch-plugin-ai-actions/      — コンテキストメニュー スマートアクション
```

### 4.3 AI Agent プラグイン（基盤）の設計

```typescript
// 他の AI プラグインが EventBus 経由で利用する API
interface AiAgentApi {
  requestCompletion(prompt: string, canvas: CanvasSnapshot): Promise<AiResponse>
  showThinking(position: Point): void
  hideThinking(): void
}

interface CanvasSnapshot {
  shapes: ShapeData[]
  viewport: Viewport
  selection: string[]
}

interface AiResponse {
  actions: AiAction[]  // addShape, updateShape, deleteShape, suggest
}
```

**既存インフラとの統合:**
- `EventBus.emit('ai:request')` / `EventBus.on('ai:response')` でプラグイン間通信
- AI の mutation → `CommandRegistry.execute()` → `BoardStore`（Undo 可能）
- AI 提案 → `TransientRegistry` の `ai-suggestion` タイプ（`TransientObject.ttl` で自動消去）
- AI カーソル → `TransientRegistry` の `ai-cursor` タイプ
- AI 生成シェイプ = 標準 `ShapeData`（特別なシェイプ型不要）

### 4.4 サーバーサイド AI プロキシ

```
apps/server/src/routes/ai.ts
  POST /api/ai/complete    — LLM API プロキシ（ストリーミング対応）
  POST /api/ai/understand  — キャンバス → 要約
```

- API キー管理、レート制限、トークンカウント
- Cloudflare Workers AI or 外部 LLM（Claude / GPT）
- SSE によるストリーミングレスポンス（AI が描く過程がリアルタイムで見える）

### 4.5 キャンバスシリアライズ戦略

`ShapeData` は既に LLM フレンドリーな構造:

- `Map<string, ShapeData>` → コンパクト JSON
- 空間的関係（重なり・近接・整列）を含む
- ビューポートで絞り込み（見えているシェイプのみ詳細、遠いものは要約）
- トークンバジェット管理

### 4.6 TransientRegistry による AI UX

| タイプ | 用途 | TTL |
|---|---|---|
| `ai-cursor` | AI のプレゼンス表示 | なし（手動制御） |
| `ai-thinking` | 処理中パルスインジケータ | なし（手動制御） |
| `ai-suggestion` | 確定/却下可能なゴーストシェイプ | 30秒 or 却下まで |
| `ai-highlight` | AI が参照しているシェイプのハイライト | 10秒 |

## 5. フェーズドロールアウト

AI 機能は既存 MVP ロードマップをブロックしない。Week 8（基本ホワイトボード完成）後に AI 開発を開始。

### Phase 0: MVP 基盤（Week 1-8、既存ロードマップ）

AI 作業なし。描画・永続化・コラボ・共有を出荷。v1 の教訓を守る。

### Phase AI-1: Canvas-Aware AI Agent（Week 9-10、2週間）

- `usketch-plugin-ai-agent` 実装
- サーバーサイド AI プロキシ (`/api/ai/complete`)
- キャンバスシリアライズ (`canvasToPrompt()`)
- AI プレゼンス（カーソル、思考中インジケータ）
- シンプルなコマンドパレット: プロンプト入力 → AI がシェイプ配置
- **出荷価値:** 「Xのフローチャートを描いて」→ 編集可能シェイプが出る

### Phase AI-2: Smart Actions（Week 11-12、2週間）

- `usketch-plugin-ai-actions` 実装
- コンテキストメニュー統合:「整理」「整形」「ラベル」「翻訳」
- 選択シェイプ + 周辺のみをシリアライズ
- **出荷価値:** 散らかったシェイプを選択して「きれいにして」

### Phase AI-3: Real-Time Copilot（Week 13-15、3週間）

- `usketch-plugin-ai-copilot` 実装
- EventBus 経由でシェイプ作成/変更イベントを購読
- ゴーストシェイプ提案（TransientRegistry `ai-suggestion`）
- Accept/Dismiss UX（クリックで確定、Esc で却下）
- デバウンスされた推論
- **出荷価値:** AI が創造的なパートナーとして感じられる

### Phase AI-4: AI Chat Panel（Week 16-17、2週間）

- `usketch-plugin-ai-chat` 実装
- サイドパネル UI + 会話履歴
- キャンバスコンテキストを会話間で維持
- **出荷価値:** 完全な会話型共同制作体験

### Phase AI-5: マルチモーダル（Week 18+、継続）

- 音声入力、画像→シェイプ、手書き認識

## 6. ビジネスインパクト

### フリーミアムモデル調整

| プラン | AI 利用枠 | 根拠 |
|---|---|---|
| Free | 10 AI アクション/日 | 価値を体験させ、アップグレード動機を作る |
| Pro（¥980/月） | 500 AI アクション/日 | 個人パワーユーザーに十分 |
| Team（¥1,980/人/月） | 無制限 | エンタープライズのニーズ、主要収益源 |

※「AI アクション」= 1 LLM 推論呼び出し。提案の閲覧はカウントしない。

### 収益インパクト

- AI 機能が Pro/Team アップグレードの主要ドライバー（非AI ホワイトボード比 2-3x コンバージョン想定）
- Team プラン + 無制限 AI がシートベース収益を牽引
- 将来: AI プラグインマーケットプレイス（レベニューシェア）、API アクセス

### コスト管理

- 軽量推論は Cloudflare Workers AI（コスト効率）
- 複雑な生成は外部 LLM（Claude / GPT）
- キャッシュ: 同一プロンプト + 類似キャンバス状態 → キャッシュ返却
- トークン最適化: コンパクトシリアライズ、ビューポートフィルタリング
- 推定コスト: 約 0.5-2 円/AI アクション

## 7. リスクと対策

| リスク | 深刻度 | 対策 |
|---|---|---|
| AI 機能が MVP を遅延 | 高 | AI は厳密に MVP 後。Phase 0 に AI コードなし |
| LLM レイテンシがリアルタイム UX を損なう | 中 | ストリーミング、思考中インジケータ、楽観的ゴースト |
| AI ハルシネーションで無意味なシェイプ | 中 | Zod スキーマバリデーション、構造化出力 |
| トークンコストが収益を超過 | 中 | 厳密なメータリング、キャッシュ、コンパクトシリアライズ |
| AI インフラの過剰設計（v1 の教訓！） | 高 | AI はプラグイン。「AI エンジン」パッケージは作らない |
| キャンバスデータの LLM 送信によるプライバシー | 高 | 明確なデータポリシー、ローカルモデル選択肢 |

## 9. 未決事項

1. **LLM プロバイダ戦略** — 単一（Claude API）or マルチ+フォールバック？→ 単一で始め、後で抽象化
2. **ローカルモデル** — Free 枠にブラウザ内モデル（WebLLM）を使うか？→ 面白いが複雑性が増す。後回し
3. **AI のアイデンティティ** — ボードごとに永続的な AI メンバーか、匿名インフラか？→ 名前付き AI「uSketch AI」推奨
4. **マルチユーザーセッションでの AI** — ユーザーごとの AI コンテキスト or 共有？→ ユーザーごとのコンテキスト、AI アクションの可視性は共有
5. **プラグイン間依存** — AI プラグイン間は EventBus（疎結合）or 明示 import（密結合）？→ EventBus 推奨
